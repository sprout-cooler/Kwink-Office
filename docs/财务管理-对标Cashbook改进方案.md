## 一、Cashbook 的功能设计（实测界面 + 文档）

### 1.1 三个核心页面

**账本日历（主视图 / 记账入口）**
- 顶部三张 KPI：总收入 / 总支出 / 结余
- 月历视图：每天一格，支出用黄块、大额标红，收入用绿块（带方向箭头）
- 每格右上角「+」= 点开即记当天的账（**日历即记账入口**）
- 月份切换 +「当月分析」快捷跳转

**数据分析（图表轮播）**
- 5 种图表按页轮播（页面显示 1/5）：
  1. 支出类型统计环形图（中心显示占比最大的分类与金额）
  2. 支付方式统计饼图
  3. 每日流水统计曲线图
  4. 每月流水统计柱状图
  5. 流水归属统计饼图
- 两个全局筛选：时间段 + 收支方向（支出/收入）
- 多账本切换（顶栏「当前账本」）

**流水管理（明细 + 工具）**
- 顶部工具条：导入导出 / 自助平账 / 新增 / 筛选 / 配置
- 四张 KPI：总收入（+）/ 总支出（−）/ 净收入 / **不计收支**（单独一块）
- 表格列：日期、流水类型（收入/支出/不计收支/转账）、支出/收入类型、**支付方式**、金额、名称、备注、**归属**、操作
- 分页（20条/页）

### 1.2 它的特色能力

| 能力 | 说明 |
|---|---|
| 多源账单导入 | 支付宝 / 微信 / 京东金融 CSV，导入时**消费类型自动转换**（映射规则用户可配置） |
| 模板导入 | 按模板批量导入 |
| 自助平账 | 收入/支出互相抵消（处理退款、AA 结算等对冲场景） |
| 预算管理 | 独立页面 |
| 小票图片 | 流水可附小票 |
| 多账本 / 共享账本 | 账本间数据独立，可多人共用 |
| 数据迁移 | 账本级 + 系统级导入导出 |

## 二、与现有模块的结构性差异

我们的财务管理**不是**通用生活记账本，而是「生意账」——
流水可关联客户 / 出差，与工作量统计共享数据维度。这个定位差异决定了不能照搬：

| 维度 | 我们（生意账） | Cashbook（生活账） | 结论 |
|---|---|---|---|
| 交易对手 | **交易方**（v1.0.33，含去重、相对方推导） | 名称（自由文本） | 我们更强，保留 |
| 客户/出差维度 | ✅ 有 | ❌ 无 | 我们的差异化价值，保留 |
| 账单导入校验 | 预览/去重/失败原因/批次撤销 | 仅导入 | 我们更强，保留 |
| 支付方式维度 | ❌ 没存（解析到了「收/付款方式」列但丢弃） | ✅ 独立字段+饼图 | **补** |
| 趋势图表 | ❌ 只有 1 张支出分类饼图 | ✅ 每日/每月/5 种 | **补** |
| 日历视图 | ❌ 无 | ✅ 主视图 | **补**（分析+快捷记账） |
| 时间筛选 | 后端支持、前端未暴露 | ✅ | **补**（成本极低） |
| 导出 | ❌ 无 | ✅ | **补** |
| 退款对冲 | 手工删/改 | 自助平账 | **补**（导入账单后尤其需要） |
| 分类映射 | 固定取账单「交易分类」 | ✅ 可配置 | **补**（可配置映射） |
| 多账本/预算/小票 | ❌ | ✅ | 远期，与生意账定位弱相关 |

## 三、改进清单（按优先级）

### P0 · 补短板（改动小、收益直接）

**1. 收支趋势图（新增 2 张图）**
- 展示：① 按月柱状图 —— 收入/支出双系列并列，一眼看净额走势；② 近 30 日曲线 —— 每日收支折线
- 实现：新增 `GET /expenses/trend?granularity=month|day&date_from&date_to`，后端按日/月聚合返回；前端复用 ChartBox + chart-theme，放在「支出分类构成」旁
- 数据展示形式：双系列柱状（收入=绿、支出=红）+ 净额虚线；悬浮显示当期收入/支出/净额

**2. 支付方式维度（新字段 + 新图）**
- 模型：`biz_expenses.payment_method`（String 32，如「支付宝」「零钱」「招商银行(1234)」）
- 解析：账单的「收/付款方式」列已有别名匹配，落库即可；导入预览一并展示
- 展示：支付方式饼图（支出口径）；流水表加一列；筛选器加下拉
- 价值：生意账里「哪个渠道在花钱」与「花在哪」同样重要

**3. 时间范围筛选（前端暴露既有能力）**
- 工具条加日期范围选择器（el-date-picker daterange），接后端已有的 date_from/date_to
- KPI（收入/支出/净额/条数）跟随筛选联动 —— 现在的 KPI 只对「类型/客户」联动，缺时间维度

**4. 财务导出**
- 展示：流水管理工具条加「导出」按钮 → 按当前筛选导出 XLSX（复用周报导出的 openpyxl 基建）
- 列：日期、类型、类别、交易方、关联客户、支付方式、金额、订单号、平台、备注
- 说明：本项目至今**没有**财务导出功能（用户问「导出表头」时核实过），这是从零新增

### P1 · 对齐 Cashbook 的核心体验

**5. 记账日历视图（数据大屏新增一个子 Tab 或财务页内切换）**
- 展示：月历，每天显示 支出（黄/超阈值红）/收入（绿），日格点「+」打开预填当天日期的新增流水表单
- 月历上方三张 KPI（当月总收入/总支出/结余）+ 月份切换 +「当月分析」
- 实现：`GET /expenses/calendar?year&month` 按日聚合；前端用 el-calendar 或自绘月历网格

**6. 自助平账（退款/对冲）**
- 场景：账单导入后，退款是一笔收入、原消费是一笔支出，两者应互相抵消而不是让统计虚高
- 展示：流水管理加「平账」按钮 → 勾选一收一支两条 → 标记为一组对冲（`offset_group_id`）
- 统计口径：KPI 与图表默认剔除已对冲的组，可切换「含对冲」查看原始流水
- 表格：被对冲的两条流水打上「已对冲」标记并可点击查看对手方

**7. 分类映射规则可配置**
- 场景：导入账单时「交易分类」是平台的分类（如「餐饮美食」），我们想要自己的类别体系（餐饮/差旅/办公…）
- 展示：设置抽屉「数据大屏」Tab 加「分类映射规则」编辑区（原始分类 → 目标类别，支持通配）
- 实现：`biz_category_rules` 表（owner_uid + pattern + target_category + priority）；导入时按规则转换，未命中落「账单导入」
- 与现状关系：v1.0.32 现在直接把账单分类当类别用 —— 规则表是它的超集，向后兼容

### P2 · 远期（与生意账定位相关性较弱，暂不建议排期）

**8. 预算管理**：月度分类预算 + 超支提醒（日历/分析页显示预算进度条）
**9. 小票图片附件**：流水挂小票（需要对象存储规划，成本较高）
**10. 多账本**：我们以「客户维度」切分数据已经满足生意场景，多账本会带来隔离复杂度，暂缓

## 四、不建议照搬的部分（明确说明）

- **多账本**：Cashbook 的多账本对应「家庭多场景」，我们的数据切分维度是**客户/出差**，
  引入账本会与 owner_uid 隔离、客户关联统计产生交叉，复杂度高收益低。
- **「转账/不计收支」流水类型**：我们已有 kind=income/expense + 导入时跳过不计收支行；
  Cashbook 的「转账」类型服务于个人账户间转移，生意账场景弱。
- **支付方式作为独立表**：Cashbook 有「类型管理」页面管理支付方式与分类；
  我们用自由文本 + 可配置映射规则（P1-7）已覆盖，避免多一张管理页的维护成本。
