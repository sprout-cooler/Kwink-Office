# 财务升级为一级模块 · 实施规划

> 决策依据：对标 Cashbook 后确认——它的完整体量是 **7 前台模块 + 7 后台模块 + 自建用户体系**
> （见《财务管理-对标Cashbook改进方案.md》§1.0 的路由实证）。
> 但它是「生活账」，我们是「生意账」，且用户 NAS 上已部署 Cashbook。
> 因此选定路线：**在现有项目内把财务升级为一级模块**，不做独立应用。
> 版本目标：v1.0.35 ｜ 日期：2026-10-28 ｜ 状态：**规划中，待批准后实施**

---

## 一、目标

把「财务」从「数据大屏」的一个 Tab，升级为**顶级导航模块**，内含 5 个子页：

| 子页 | 内容 | 现状 |
|---|---|---|
| 流水明细 | 收支 CRUD、多条件筛选、XLSX 导出 | 已有（在 FinanceTab 内） |
| 账单导入 | 支付宝/微信 CSV 导入、预览、去重、批次历史 | 已有（FinanceTab + BillImportDialog） |
| 趋势分析 | 月度柱状、30 日曲线、分类饼图、支付方式饼图 | 已有（4 图，挤在 FinanceTab 里） |
| **预算** | 月度总预算/分类预算、执行进度、超支提示 | **新增** |
| **分类与映射** | 自建分类体系、三方账单分类→自建类别的转换规则 | **新增** |

同时保留的核心约束：**流水 ↔ 客户 ↔ 出差 ↔ 工时仍在同一数据库、同一 `owner_uid` 隔离下**，
不引入任何跨应用同步。

## 二、现状盘点（已实测，非推断）

### 2.1 模块注册机制
- 后端 `server/app/modules/registry.py`：`MODULES` 元组定义模块（id / display_name / icon / route / tabs）；
  `list_enabled()` 输出给前端。
- 前端**没有 vue-router**：`web/src/shell/AppShell.vue` 直接 `import` 三个 Panel
  （`WeeklyReportPanel` / `ImageToolPanel` / `BizDashboardPanel`），
  按 `store.activeModuleId` 切换；`BizDashboardPanel` 内部再按 `store.activeTabId` 切换各 Tab。

> 这意味着「拆模块」的工作量主要在**前端页面重组 + registry**，
> 后端 API 路径可以完全不变（仍是 `/biz-dashboard/expenses/*`）。

### 2.2 现有财务相关文件

| 文件 | 作用 |
|---|---|
| `web/src/modules/biz_dashboard/FinanceTab.vue` | 当前财务全部能力（KPI + 4 图 + 筛选 + 表格 + 导入弹窗） |
| `web/src/modules/biz_dashboard/BillImportDialog.vue` | 账单导入弹窗（上传→预览→确认） |
| `web/src/modules/biz_dashboard/ChartBox.vue` | 图表容器 |
| `server/app/modules/biz_dashboard/router.py` | 约 40 条路由（客户/出差/财务/工时/分享/地图） |
| `server/app/modules/biz_dashboard/service.py` | 业务实现（含 v1.0.32-34 的导入、交易方、趋势、导出） |
| `server/app/db/models.py` | `biz_expenses` / `biz_shares` / `biz_expense_imports` 等 |

### 2.3 已完成的前置改动（本轮规划前的探查产出）

以下三处**已写入工作区**，但尚未接线（不影响现有功能运行）：

1. `db/models.py` 新增两张表：`biz_budgets`、`biz_category_rules`
2. `service.py` 新增预算 CRUD + 进度、分类规则 CRUD + 匹配函数
3. 《财务管理-对标Cashbook改进方案.md》补正：Cashbook 完整路由清单 + 独立项目论证

⚠️ 有一处**已主动回滚**：`registry.py` 里曾提前注册 `finance` 一级模块，
但前端尚无对应 Panel，切过去会白屏 —— 已恢复为「数据大屏 → 财务管理」Tab。
**该步骤必须在前端 Panel 就绪后同步开启**（见 Step 4）。

## 三、数据模型设计

### 3.1 `biz_budgets`（月度预算）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Integer PK | |
| owner_uid | String(64) 索引 | 数据隔离 |
| period | String(7) 索引 | `YYYY-MM`，与 `occurred_on` 前 7 位同形 |
| category | String(64) | **空串 = 当月总预算**；非空 = 分类预算 |
| limit_amount | Numeric(14,2) | 限额 |
| created_at / updated_at | DateTime | |

- 唯一约束 `(owner_uid, period, category)`：同月同类只允许一条，重复设置时给出
  「已设置过，请直接修改它」的可行动提示，而不是抛唯一约束错误。
- **只存限额，不存已用**：已用金额实时从 `biz_expenses` 汇总。
  存副本必然与流水对不上，那是最难排查的一类脏数据。
- period 用字符串比较而不是日期函数：SQLite 与 PostgreSQL 行为一致，
  且能直接命中 `occurred_on` 的前缀。

### 3.2 `biz_category_rules`（账单分类映射规则）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Integer PK | |
| owner_uid | String(64) 索引 | |
| platform | String(16) | `alipay` / `wechat` / `unknown`；**空串 = 通用规则** |
| pattern | String(64) | 待匹配的原始分类文本 |
| match_mode | String(16) | `exact` 全等 / `contains` 包含 |
| target_category | String(64) | 转换后的自建类别 |
| priority | Integer | 降序，多条命中取优先级最高 |
| enabled | Integer | 0 = 停用（可临时关闭而不必删除） |

- 匹配顺序：priority 降序 → id 升序，保证结果**稳定可预期**。
- **未命中返回原值，绝不猜测**：分类配错会污染所有分类统计，宁可保留平台原始值
  让用户在导入预览里看到并处理。
- 对应 Cashbook 的 `/admin/typeRelations`（后台类型关系）——我们放在普通用户页，
  不做后台管理（本应用单用户/单 NAS 账号场景，不需要后台用户管理）。

## 四、分步实施计划

### Step 1 · 后端：预算接口（半天）
**改动**：`router.py` 新增
- `GET /biz-dashboard/budgets?period=` 列表
- `POST /biz-dashboard/budgets` 新增
- `PATCH /biz-dashboard/budgets/{bid}` 修改
- `DELETE /biz-dashboard/budgets/{bid}` 删除
- `GET /biz-dashboard/budgets/progress?period=YYYY-MM` 执行进度

**验收**：curl 实测——设 2024-08 总预算 5000、餐饮预算 800；
导入/新增若干 8 月支出后，`progress` 返回的 `used / remaining / percent / over` 正确；
跨用户数据不串（用另一个 uid 请求返回空）。

### Step 2 · 后端：分类映射规则 + 导入时应用（半天）
**改动**：
- `router.py`：`GET/POST/PATCH/DELETE /biz-dashboard/category-rules`
- `service.commit_bill_import` / `preview_bill_import`：写入 category 前先过
  `match_category(txn_type, platform, rules)`（规则一次性加载，避免逐行查库）
- 导入预览表增加一列「映射后类别」，让用户看到规则生效后的结果

**验收**：配一条「餐饮美食 → 餐饮（contains）」规则；
导入含「餐饮美食」的支付宝账单，预览里映射后类别显示为「餐饮」，落库一致；
规则停用后导入则保留原值。

### Step 3 · 后端：注册一级模块（10 分钟，**必须最后做**）
**改动**：`registry.py`
- 新增 `ModuleMeta(id="finance", display_name="财务", icon="finance", route="/finance",
  tabs=(flows/import/analysis/budget/category))`
- 从 `biz_dashboard` 的 tabs 中**移除** `finance`

**验收**：`/api/session` 返回的模块列表含 finance；**且前端已能渲染该模块**（否则白屏）。

### Step 4 · 前端：新建 finance 模块骨架（1 天）
**改动**：
- 新建目录 `web/src/modules/finance/`
- `FinancePanel.vue`：按 `store.activeTabId` 切换 5 个子页
- 子页组件：
  - `FlowTab.vue`（从 FinanceTab 拆出：KPI + 筛选 + 表格 + 导出）
  - `ImportTab.vue`（从 FinanceTab + BillImportDialog 拆出：导入 + 批次历史）
  - `AnalysisTab.vue`（4 张图表）
  - `BudgetTab.vue`（新增）
  - `CategoryTab.vue`（新增）
- `AppShell.vue`：`import FinancePanel` 并加入模块切换分支
- 图标 `finance` 需在图标集中存在（否则回退到默认图标）

**验收**：左侧导航出现「财务」，5 个 Tab 可切换；深浅色与窄屏（390/768）无横向溢出。

### Step 5 · 前端：预算页与分类页（1 天）
- **BudgetTab**：月份选择器（默认当月）+ 总预算/分类预算列表 + 进度条
  （<80% 正常、80-100% 警告色、>100% 红色标「超支」）+ 新增/编辑/删除
- **CategoryTab**：现有类别概览（各类别的流水数与金额）+ 映射规则表格
  （平台/关键词/匹配方式/目标类别/优先级/启停）+ 新增/编辑/删除/停用

### Step 6 · 验证与发布（半天）
- 308+ 单测（新增预算进度、规则匹配优先级、归属隔离等约 15 项）
- `vue-tsc` 零报错、`vite build` 通过
- 浏览器截图：5 个子页 × 深浅色 × 窄屏
- 真机 PostgreSQL 迁移验证（`biz_budgets` / `biz_category_rules` 两表建成 + 唯一约束生效）
- 打包 fpk → 构建推送镜像 → tag v1.0.35 → 推 Gitee/GitCode/GitHub 三远端

## 五、风险与取舍（明确列出）

| 项 | 风险 | 应对 |
|---|---|---|
| registry 提前注册 | 前端无对应 Panel → 切过去白屏 | **Step 3 必须与 Step 4 同步验收**，本轮已提前回滚一次 |
| 财务 Tab 移除后旧链接 | 用户习惯的「数据大屏→财务管理」入口消失 | 数据大屏总览保留「财务摘要卡片 + 跳转财务模块」，路径变化有引导 |
| 预算与分类是新概念 | 用户可能不需要 | 两者都是 Cashbook 的一级模块，且是「把财务做大」的必经项；可先做预算，分类映射后置 |
| 后端仍放 biz_dashboard | 模块名与前端不一致（前端叫「财务」，后端目录叫 biz_dashboard） | **刻意如此**：财务与客户/出差/工时共用数据层与外键，拆后端目录会引入跨模块 import 与循环依赖，收益不抵复杂度 |
| 金额精度 | 预算进度用 float 累加 | 汇总用 Numeric 求和后再转 float，仅在展示层转，与现有 KPI 口径一致 |
